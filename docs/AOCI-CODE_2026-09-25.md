## 项目简介
AOCI-CODE（AI-Oriented Cognition Infrastructure）是给 AI Agent 建的**持久化代码库认知地图**。它把源码、配置、测试、数据库结构蒸馏成高信息密度的纯文本索引，随项目一起 Git 版本管理。Agent 动手前先读完索引，一遍获得系统全局认知，而不是每个任务重新爬仓库。

它与静态符号图（CodeGraph 等）是**两种不同哲学**：机器抽的是"谁调用谁"，LLM 写的是"这段代码有什么不能猜的约束"。

## 核心机制：FRAS 四段式

每条索引一行，对象可以是一个源文件，也可以是一张数据库表：

```text
atomic.go[CG9L]: F:提供持久化 replace CAS、原子写、no-clobber 恢复
  | R:internal/fs/atomic_exchange_linux.go,lock.go
  | A:AtomicWrite,AtomicWriteCAS,AtomicCreateCAS
  | S:原生发布绝不降级为覆盖式 rename；遇竞态/类型不安全/字节不可验证时必须保住第三方状态
```

- **F（Function）**：这个对象负责什么
- **R（Relations）**：要安全改动它，必须一并理解哪些文件/模块/数据库对象
- **A（API）**：它暴露哪些接口、命令、格式、可观测契约
- **S（Synopsis）**：F/R/A 都没表达、但改错就出事的约束——事务边界、授权、并发、缓存、部署、兼容性、历史包袱

前置的 `[CG9L]` 是多维符号标签：架构层、业务域、重要性（9/8/7/5/3/1 六档）、技术特征、代码规模。它让模型先建立"这个对象在系统里处于什么坐标"的结构认知，再读语义。

## 索引文件布局（Volumes v1）

| 文件 | 作用 |
|------|------|
| `aoci.txt` | Root：声明当前 CognitionSet 包含哪些卷 |
| `aoci.meta.txt` | Meta：标签字典、FRAS 规则、长度预算、写作契约 |
| `aoci.code.txt` | Code 卷：代码对象条目 |
| `aoci.database.txt` | Database 卷：数据库表级条目（可选，默认不启用） |
| `.aoci/` | config.json（团队策略）、baseline.json（受治理基线）、curation.json、事务与恢复证据 |

条目之间**互相独立**，只依赖自己的源文件，跨文件关系写在 R 字段里。所以改一个文件只需重新生成那一条，不用重建整张索引。

## 关键设计取舍

1. **模型拥有语义**：AOCI 不从文件名、目录、AST 凭空编造业务语义。首轮索引质量完全取决于当时的模型是否真读懂了代码——这是它与静态分析的根本区别，也是风险所在。
2. **只读 Root 不算读完**：README 明确警告，只读 `aoci.txt` 不足以声称获得完整系统认知，必须读 Meta + Code + Database 卷。
3. **Git 边界严格**：认知资产本身要走 Git（可 diff、可评审、可回滚），但 `.aoci/` 下的草稿、Ledger、事务、恢复证据通常不进 Git。认知资产若被 gitignore，`scan` 会静默跳过，索引建不起来。
4. **宿主绑定绝对路径**：`init` 写入的 `.mcp.json` / `.claude/settings.json` / `.codex/config.toml` / `opencode.json` 内含机器绑定的绝对路径，必须 gitignore，否则换机器就断。
5. **索引不由 AOCI 自动生成**：CLI 只做扫描和治理，语义条目由 Agent 按协议流程（Plan/Stage/Check/Diff/CAS/Apply）撰写。

## 两种工作模式

- **code-to-index**：读现有仓库，生成结构化索引（存量代码接入）
- **index-first**：开发先用自然语言描述需求，模型产出完整索引作为架构蓝图，**先评审索引再写代码**——把评审对象从几万行代码压缩到几百行索引

## 规模与性能

- 声称可处理约 50 万行代码；作者称 70 万行商业系统已用此法开发，索引约 300K token
- 论文实测：4 项目 × 3 LLM × 6 上下文条件共 2160 次评测；19 个工业任务中零最终态缺陷，3 个主流 Agent 工具在 12 个任务上引入缺陷且多耗 4–130 倍 token

## 兼容性与安装

```bash
# 1. 从项目根运行
AOCI=/absolute/path/to/aoci-code/build/aoci
"$AOCI" --repo . init --locale zh-CN --agent codex   # 或 claude/cursor/opencode
"$AOCI" --repo . scan

# 2. 重启宿主（刚写入的 MCP 工具在本会话不可见）
# 3. 在 Agent 里下指令：先确认 AOCI MCP 已连接，然后为本项目构建 AOCI 索引
```

- 宿主：Codex、Claude Code、Cursor、OpenCode 等
- 数据库索引：PostgreSQL、MySQL、openGauss 6.0.5（**达梦未在支持列表**）

## 与 CodeGraph 的选型对比

| 维度 | AOCI-CODE | CodeGraph |
|------|-----------|-----------|
| 索引内容 | LLM 撰写的语义（S 字段是杀手锏） | 机器抽取的符号/调用边 |
| 生成成本 | 消耗 token | 零（无 LLM） |
| 正确性 | 取决于模型理解 | 确定性可复现 |
| 承载形态 | 纯文本，进 Git，可 diff/回滚 | SQLite，不进 Git |
| 读取方式 | 任务前全量读索引 | 按需查询 |
| 维护 | Agent 走治理流程 | 文件监听自动同步 |
| 成熟度 | 7 周 RC | 8 个月，72k 星 |

**互补关系**：CodeGraph 回答"改这个函数谁会炸"，AOCI 回答"这条链路有什么不能违反的约束"。

## 风险与注意事项

- ⚠️ **RC 阶段**：v0.1.0-rc15，建仓仅 7 周，8 个 open issue
- ⚠️ **许可证不明确**：README 徽章同时标 FSL-1.1 与 MIT，GitHub API 识别为 NOASSERTION，**商业交付前必须让法务确认 FSL 条款**
- ⚠️ **7 个论文基准库不含 C++**：论文的工业验证覆盖 Go/Node.js（教育、法律、金融领域），C++ 场景无公开数据
- ⚠️ **强依赖宿主配合**：MCP 9 个工具要 Agent 主动按协议走完整治理流程，普通对话式 Agent 用不到完整能力
- ⚠️ **达梦兼容性未知**：数据库索引只明确支持 PostgreSQL/MySQL/openGauss
- ⚠️ **首轮索引质量不可控**：如果建索引的模型能力不足，产出的 S 字段可能是编造的——这比没有索引更危险

## 不适用场景

- 小于几万行的项目（索引开销大于收益）
- 一次性/临时脚本代码
- 要求绝对确定性的场景（不能单靠它，首轮质量依赖模型）
- 没有强模型可用的环境（建索引本身要消耗大量 token）
- 达梦数据库索引（未验证）
- 商业交付且法务未确认 FSL-1.1 条款前
