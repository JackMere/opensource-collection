## 项目简介

Dayflow 是 macOS 上的**自动工作日志**。它静默采集你的屏幕活动，用 AI 把一天还原成一条可读的时间线——**不需要手动开计时器，也不需要记笔记**。

它解决的核心问题是：**普通时间追踪工具只告诉你「哪个 App 开着」，Dayflow 试图理解「你到底在干什么」。** 例如「Cursor 开了 2 小时」可能是在交付功能、调 auth bug、审 PR，或只是卡在环境配置上——Dayflow 给的是上下文，不是窗口标题。

**本地优先 + 开源 + MIT**：录屏、时间线、数据库默认只存本机 `~/Library/Application Support/Dayflow/`，且可配置为完全用本地模型运行。

## 核心功能

1. **自动时间线**：采集轻量屏幕片段 → AI 分析 → 转成当天的活动卡片，无需计时器或手写记录
2. **上下文感知摘要**：分析屏幕实际内容，而非仅窗口标题
3. **每日站会**：GitHub 风格活动网格 + 昨日亮点 + 今日任务 + 阻塞项，**站会发言稿自动写好**
4. **与工作日志对话**：用自然语言问「这周干了什么」，答案基于时间线而非凭记忆
5. **周度复盘**：聚合出专注模式、分类、App 占用、交互图谱（热力图 / 矩形树图 / 桑基图 / 环形图均自建）
6. **分心追踪**：识别走神时段，与专注工作并列展示
7. **Markdown 导出**：任意日期范围导出，便于喂给 LLM 或写周报
8. **自动清理**：可配置存储上限，自动清除旧录像，避免占满磁盘
9. **AI 提供方可选**：本地模型（Ollama / LM Studio）或云端（Gemini / ChatGPT / Claude CLI）

## 技术机制（源码级）

### 采集与分析流水线

```
每 10 秒采集 1 帧（默认，可选 1/5/10/20/30/60 秒）
      ↓  缩放到 720p 或 1080p
攒满 15 分钟 → 合成为 MP4 视频
      ↓  时间压缩：真实 900 秒 → 视频 90 秒（10 倍压缩）
上传视频给模型（1 fps，1 张截图 = 视频里 1 秒）
      ↓  转写为「观察记录」（Observations）
再由观察记录生成「活动卡片」（纯文本）
```

关键参数（`LLMTypes.swift` / `GeminiDirectProvider+Transcription.swift`）：

| 参数 | 值 |
|------|-----|
| 采集间隔 | 默认 **10 秒**（非 1 fps） |
| 批次时长 | **15 分钟** |
| 批次切分 | 间隔超 **2 分钟**则切分 |
| 出卡回看窗口 | **45 分钟** |
| 合成视频 | 1 fps、**720p**、**1.2 Mbps** H.264 |

### 成本控制设计（三层）

**① 空闲批次直接跳过模型**（`IdleBatchClassifier.swift`）

四项条件全满足则**完全不调用 LLM**，直接写一张空闲卡片：

| 条件 | 阈值 |
|------|------|
| 批次时长 | ≥ **12 分钟** |
| 有效空闲采样占比 | ≥ **90%** |
| 空闲判定阈值 | 空闲 ≥ **60 秒** |
| 数据覆盖率 | ≥ **95%** |

状态标记为 `idle_shortcut_applied`。实际可省掉 25~50% 花费（午休、开会、离席时段零消耗）。

**② 过短批次标记 `skipped_short`**，不进模型。

**③ 本地模型零成本路径**：内置视觉语言模型预设，跑在本机则 API 费用为 0、数据不出机器。

| 预设 | 模型 | 拉取命令 |
|------|------|---------|
| **推荐** | Qwen3-VL 4B | `ollama pull qwen3-vl:4b` |
| 备选 | Qwen2.5-VL 3B | `ollama pull qwen2.5vl:3b` |

### 源码模块结构

`Core/` 下 11 个模块，设计完整：

| 模块 | 关键内容 |
|------|---------|
| AI | 70+ 文件，Claude / Codex / Gemini / Ollama / OpenAI 兼容各成一套 Provider，统一走 `LLMProviderRouting` |
| Recording | `ScreenRecorder` 采集、`FrameStore` 存帧、`StorageManager`（20+ 扩展）、`VideoProcessingService` 合成延时视频 |
| Analysis | `AnalysisManager` + `IdleBatchClassifier` |
| Weekly | 自建热力图 / 矩形树图+桑基图 / 环形图 |
| Security | `KeychainManager` 密钥入钥匙串 |
| **AgentAccess** | `AgentBridgeServer` + `CodexMCPRegistration` —— **通过 MCP 让 Codex 等 agent 读写工作日志** |

> ⚠️ 应用沙箱为关闭状态（`app-sandbox = false`，录屏必须如此），意味着权限较大。

## 使用场景

1. **写站会/周报**：昨日亮点 + 今日任务 + 阻塞项自动生成
2. **回答「时间去哪了」**：周度复盘给出专注模式与分心分布
3. **个人工作回顾**：作为可检索的工作档案，替代翻截图和凭记忆
4. **给 LLM 提供上下文**：导出 Markdown 时间线，喂给 AI 做总结
5. **Agent 集成**：通过 MCP 让编码 agent 读取你的工作记录

## 优势与特点

### 优势
- **本地优先 + MIT 开源**：录屏与数据库存本机，代码可审计，数据可随时删除
- **成本控制有真设计**：空闲批次跳过 LLM + 视频压缩 + 可选本地模型，不是简单粗暴地全量分析
- **AI 后端完全可插拔**：云端（Gemini/ChatGPT/Claude）与本地（Ollama/LM Studio）自由切换，可在隐私、成本、质量之间取衡
- **原生体验**：SwiftUI 原生 macOS 应用，非 Electron 套壳
- **迭代活跃**：2026 年 7 月 v2.0.2 → 9 月 v2.5.0，两个月 5 个中版本

### 注意事项
- **仅支持 macOS 14+**，且需屏幕录制权限；Windows / Linux 用户需用社区移植版（成熟度差距大）
- **应用自身不统计 token 消耗**：`LLMCall` 结构仅有 timestamp / latency / input / output，无任何 token 字段，用户无法在应用内看到花费，只能查云端后台账单
- **用云端模型需注意免费额度限流**：代码中大量处理 429（`rate limit` / `quota`），并内置备用提供商自动切换，说明撞限流是常态
- **磁盘占用**：1080p / 10 秒间隔下约 **10.3 MB/小时**，一天 8 小时约 82 MB（需配合自动清理）
- **应用沙箱关闭**，权限范围较大，介意者应审阅源码后再用
- **同名项目多**：搜 DayFlow 有 1,700+ 结果，另有 Windows 移植版（SeiShonagon520/Dayflow、zhanyutx/Dayflow_for_windows）、Rust 复刻版（deletexiumu/screen-analyzer），以及与时间追踪**完全无关**的同名项目（evadne/DayFlow 是 2013 年的 iOS 日期选择器、OlivisMo/DayFlow 是日历组件库）
