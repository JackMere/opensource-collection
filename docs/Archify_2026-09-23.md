## 项目简介

Archify 是一个**面向编码 Agent 的技能（Agent Skill）**，把「你想理解、规划或分享的东西」变成可交互的视觉图。它支持五种图形类型——**架构图（Architecture）、工作流图（Workflow）、时序图（Sequence）、数据流图（Data Flow）、生命周期图（Lifecycle）**，输入可以是一句描述，也可以是一个真实代码库。

产物是**单文件自包含 HTML**：无需安装任何东西就能在浏览器打开，带节点聚焦、路径追踪、分章讲解与演示模式，可直接转发给他人（交互一并带走）。它**不是**通用绘图编辑器，也**不是** Mermaid 主题——它的定位是「把技术意图转化为沟通产物」。

2026 年 9 月 1 日曾登上 **GitHub Trending 周榜全语言第一名**，并被量子位（QbitAI）专访报道。

## 核心功能

### 1. 五种图形类型，各有适用面

| 类型 | 最适合表达 | 提示词中应包含 |
|---|---|---|
| **Architecture** | 组件、服务、存储、边界 | 范围、核心组件、主路径 |
| **Workflow** | CI/CD、审批、工具调用、运维手册 | 参与者、顺序、分支、异常 |
| **Sequence** | API 调用、缓存回退、鉴权、异步链路 | 调用方、被调方、返回、时序 |
| **Data Flow** | 管道、血缘、PII、消费方 | 源、变换、存储、边界 |
| **Lifecycle** | 状态、重试、等待、终态 | 状态、事件、重试与取消路径 |

## 工程机制：它凭什么「可验证」

这是 Archify 与同类「让 AI 画图」工具的核心差异。它的主张是**先类型化、再渲染**：

1. **类型化 JSON IR** —— 每种图形都有独立 schema（`architecture/workflow/sequence/dataflow/lifecycle.schema.json`），Agent 生成的是可复现的结构化源，而非一次性 HTML。
2. **原子化校验** —— schema、布局、HTML/SVG、路由、标签与路径避让五类检查**全部通过**，候选产物才会替换上一个已验证版本（"last known good"）。
3. **失败带可修复回执** —— `validate --json` / `deliver --json` 失败时输出稳定规则码、精确主体、实测证据与**受支持的修复项**，而不是一段 Node 堆栈；修正轮次限定为两轮。
4. **last-good 实时预览** —— 可选的桌面模式（仅监听 `127.0.0.1` 随机端口）监视单个 JSON 文件，只有通过全部闸门的修订才刷新；保存不完整或非法时**保留上一版已验证图**。
5. **布局由判断力而非通用算法决定** —— Agent 决定层级、间距、路径与强调；共享的自动端点确定性展开，避免箭头全堆在一个中点。

### 真实性的两条硬约束

- **交互只复用「已授权（authored）」的节点与关系** —— 聚焦、上下游可达、精确路径、角色对比（Lens）、故事线都基于作者写下的结构，**不臆造拓扑、不声称运行时影响**。
- **举证按需开启** —— 需要来源证据时，架构节点标注 `SRC n`，可打开**锚定到某一公开 commit 的 Git 已验证文件与行号**；普通产物保持无来源引用。

### Architecture Delta（用于设计与 PR 评审）

对比 Before / Delta / After 三份已验证快照并给出**机器可读回执**：

```bash
node archify/bin/archify.mjs compare architecture base.json head.json architecture-delta.html --json
```

它只呈现「已授权事实」的**新增、删除、变更、移动**，明确**不推断**影响面、风险或合并安全性——这一点在评审场景里反而更可信。

## 安装与使用

```bash
# 安装（全局，适配 Cursor / Claude Code / Codex CLI / opencode）
npx skills add tt-a1i/archify -g

# 不安装、直接试用
npx skills use tt-a1i/archify@archify --agent codex

# 指定 Agent 的非交互安装
npx -y skills add tt-a1i/archify --skill archify --agent cursor --global --copy --yes

# DeepSeek Harness 社区集成（非官方产品）
dsh plugin --profile web add @tt-a1i/archify-dsh@0.1.0
```

发送给 Agent 的提示词示例：

```text
Use Archify to draw: Browser -> API -> Redis cache -> PostgreSQL fallback.
```

从代码库生成（要求带来源证据）：

```text
Analyze this repository, then use archify to create a high-level runtime architecture diagram.
Show 8–12 core components, one primary path, external dependencies, and trust boundaries.
Put supporting detail in cards instead of adding more edges.
```

CLI 命令（Node 零依赖）：

```bash
cd archify
node bin/archify.mjs doctor
node bin/archify.mjs guide "Show an API request with Redis cache miss"
node bin/archify.mjs validate workflow examples/agent-tool-call.workflow.json --quality showcase --json
node bin/archify.mjs deliver workflow examples/agent-tool-call.workflow.json /tmp/workflow.html --quality showcase --open --json
```

**运行要求**：Node.js `^22.19.0 || >=24.0.0`。

## 交互与导出

| 操作 | 快捷方式 |
|---|---|
| 打开图表指南 | `?` |
| 查找并聚焦节点 | `/` |
| 追踪上下游可达 | 聚焦节点 → `Upstream` / `Downstream` |
| 探查有向路径 | `R` 或 `PATH` |
| 对比 1–2 个角色 | `L` 或 `LENS` |
| 全图雷达总览 | `M` 或 `MAP` |
| 播放故事线 / 切换章节 | `P` / `[` `]` |
| 演示舞台 | `F` |
| 切换视觉风格 / 主题 / 导出 | `S` / `T` / `E` |

- **可分享链接**：支持 `#focus=<id>`、`#route=<source>~<target>`、`#lens=<kind>~<kind>`、`#view=<view-id>` 等状态还原。
- **导出**：PNG 复制到剪贴板、静态/动图下载、**1200×630 分享卡**（README / release / 社交图），以及 Route Share Card（保留全图作上下文的路径卡）与 Reach Share Card。
- **动效**：读者驱动的动效是**有限**的，尊重 `prefers-reduced-motion`，且**永不进入正式导出**。
- **国际化**：`meta.locale = en | zh-CN` 本地化页面标题、图例、状态/错误、无障碍标签与 HTML/SVG `lang`（不翻译作者内容）。

## 使用场景

- **理解陌生代码库** —— `CODE → DIAGRAM`，产出带 Git 证据的系统地图（官方示例：追踪 `mco-org/mco` @ `9f1a1cf` 生成运行时架构图）。
- **设计与 PR 评审** —— Architecture Delta 三快照对比。
- **Agent 工作流说明** —— 把工具调用链路画成可播放的分章故事。
- **对外沟通** —— 单文件 HTML 转发，或导出分享卡贴进文档/群聊。
- **非技术场景**（社区创造）—— 行程规划、学习地图、合同评审、事故复盘；已有用户把生成的架构图带进**飞书 / 钉钉**做团队讨论。

## 优势与特点

- **产物是单文件 HTML** —— 无运行时依赖，离线可看，转发即带走交互。
- **可验证性设计** —— 类型化 IR + 原子校验 + 可修复回执 + last-good 预览，把「AI 画图」从一次性产物变成可迭代工程。
- **不撒谎的交互** —— 只展示作者写下的结构，不臆造运行时影响。
- **证据可锚定 commit** —— 需要时能给出行级来源。
- **隐私极简** —— 更新检查仅 GET 固定 manifest 提醒，不下载不安装；服务器只看到常规 HTTP 元数据（IP 与时间），**不发送版本、Agent、项目数据、提示词、账号/设备 ID 或 ETag**；可用 `ARCHIFY_UPDATE_CHECK_DISABLED=1` 完全关闭。
- **中文友好** —— 有 `README_ZH.md`，社区含微信群与 QQ 群（1121948602）。

## 局限与注意事项

- **不解析 Mermaid** —— 官方明确「自动解析 Mermaid」**不在范围内**。已有的 Mermaid 图**无法导入**，需重新描述或转写为类型化 JSON IR。
- **无通用自动布局** —— 布局质量取决于 Agent 的判断力，不是通用布局引擎的确定性输出。
- **无托管分享 / 无 WYSIWYG 编辑** —— 同样在范围外。
- **依赖 Agent 与 Node** —— 生成环节需要宿主 Agent + Node.js；Claude.ai 场景「取决于沙箱内是否有 Node 访问权限」。
- **需要联网的**：外部网站链接、地图链接（产物本身仍可离线打开）。
- **项目极年轻** —— 2026-04-15 创建，约 5 个月；**个人开发者**项目，无公司实体背书；154 个开放 issue。
- **未经信创/ARM64 验证** —— 未在银河麒麟等国产化环境实测。

## 适用性判断

### 对本机（Linux 服务器）

| 检查项 | 结果 |
|---|---|
| Node 版本 | ✅ **v22.23.1**，满足 `^22.19.0 \|\| >=24.0.0` |
| npx | ✅ 10.9.8 |
| 技能自包含性 | ✅ `archify/bin/archify.mjs` 为**零依赖 CLI**，schemas / examples / viewer / 字体（JetBrains Mono OFL）均随仓库提供 |
| 可离线分发 | ✅ 产物是单文件 HTML，浏览器直接打开 |

**结论**：本机具备运行条件。⚠️ 但需注意 Archify **官方适配列表里没有 Hermes Agent**（支持 Cursor / Claude Code / Codex CLI / opencode / Claude.ai / Project Knowledge / DeepSeek Harness）。由于 Hermes 的技能同样是 `SKILL.md` 形态且能执行 shell，**理论上可手工放入 `~/.hermes/skills/` 试用，但未经验证**。

### 对 VTF 工作的适用性

**✅ 适用**

| 场景 | 说明 |
|---|---|
| **申报↔回报字段映射、接口时序** | Sequence 类型正对口——这是你当前的痛点之一，时序图能把「谁调谁、返回什么」讲清楚 |
| **VTF 平台架构图** | 行情回放 / 撮合引擎 / 策略中心 / 结算与银行模拟网关的多模块关系 |
| **培训教材配图** | 你偏好单文件 HTML 讲义——Archify 产物本身就是单文件 HTML，且带交互与演示模式 |
| **PR 评审** | Architecture Delta 对比三份快照，且**不推断影响面**（对合规留痕反而更稳） |
| **信创内部分发** | 产物离线可看，不依赖 CDN，适合内网传阅 |

**⚠️ 需要注意**

| 事项 | 说明 |
|---|---|
| **不能替代你的 Mermaid 资产** | 你现有讲义用 Mermaid；Archify 不解析 Mermaid，**已有图无法直接导入**，需重画 |
| **生成环节要调模型** | 生成 IR 需要能力足够的模型。若想用你自己的 New API 网关，须把**宿主 Agent**（Claude Code / Codex 等）指向该网关，Archify 本身不管模型 |
| **图表真实性靠约束而非 AI 自觉** | 它的「不臆造」来自只渲染 authored 结构。**作者写错，图就错**——所以生成后仍须人工核对关键关系 |
| **项目太年轻** | 5 个月、个人项目、154 open issues。作为**个人效率工具**可用；**不宜进入客户交付链路** |
| **ARM64 / 麒麟未测** | 红塔信创环境未验证 |

**🔴 不建议**

- 把 Archify 产物作为**对客户的正式交付物**（无公司背书、版本仍在 dev、无 SLA）。
- 在**无法使用 Agent** 的受限环境下依赖它（生成环节必须有 Agent + Node）。
