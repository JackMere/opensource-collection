## 项目简介

Next Terminal 是一款开源的 **HTML5 远程桌面网关 / 堡垒机**，核心思路是「把运维入口收敛到浏览器」：管理员在页面里登记资产（服务器、Windows 主机、网络设备），运维人员点一下就通过 WebRTC/Web 协议连进去，不需要在本地装 PuTTY、Xshell、mstsc 或 VNC 客户端。所有会话自动录像存档，可按用户、资产、时间检索回放，用于等保与内控审计。

## 核心功能

1. **多协议 Web 接入**：RDP、SSH、VNC、Telnet、HTTP/HTTPS 全部在浏览器内完成，无需插件。
2. **会话录像与回放**：全程录屏，支持按资产/用户/时间检索，是堡垒机最核心的合规能力。
3. **指令审计**：SSH 会话记录输入命令，可全文检索。
4. **资产与账户管理**：资产分组、账号凭据集中托管，运维人员只拿到「访问权」而非「密码」。
5. **细粒度授权**：按用户/用户组 + 资产/资产组配置访问策略。
6. **计划任务**：批量对资产执行命令或脚本（类似轻量版自动化运维）。
7. **单机部署**：一个 Go 二进制 + 内置 SQLite，也可以切 MySQL；没有重依赖。

## 安装与使用

```bash
# Docker 方式（最省事）
docker run -d --name next-terminal \
  -p 8088:8088 \
  -v /opt/next-terminal/data:/usr/local/next-terminal/data \
  dushixiang/next-terminal:latest

# 访问 http://<ip>:8088，默认账号 admin / admin
```

## 与「支持国产数据库达梦」需求的差距（重要）

Next Terminal **不是**为信创环境设计的，两个层面都对不上：

1. **自身数据存不进达梦**：它只支持 SQLite / MySQL。把元数据库换成达梦需要改 GORM 方言并重写迁移脚本，属于二次开发。
2. **不能把达梦当成被审计资产**：它的资产类型只有主机和网络设备，没有数据库协议通道。

如果诉求是「审计对达梦数据库的运维操作」，Next Terminal 做不到；需要看 JumpServer 这类带数据库资产通道的产品。

## 使用场景

- 团队十几个人管几十台 Linux/Windows 服务器，想要一个统一入口 + 录屏留痕，不想买商业堡垒机。
- 开发/测试环境需要「谁能连哪台机」的可追溯记录。
- 临时跳板：把内网机器通过一台公网入口收敛，配合审计。

## 优势与特点

- **门槛最低**：一个二进制跑起来，没有 Java/中间件依赖，小团队自建堡垒机的首选。
- **录像开箱可用**：商业堡垒机最值钱的功能就是会话审计，这块它做得很完整。
- **UI 现代**：相比 Apache Guacamole 的原生界面，Next Terminal 更接近国内运维的使用习惯。
- **协议覆盖广**：RDP + SSH + VNC + Telnet 一套搞定，Guacamole 之外的轻量替代。

## 注意事项

- 社区活跃度中等（2026-10 有提交），生产环境用建议锁版本。
- 官方文档主要靠官网和 GitHub Wiki，中文资料比 JumpServer 少。
- 高可用、多组织隔离、双因子等国密相关能力缺失，等保三级以上的场景要评估。
