But while doing so, they **take away your control** and make bugs in the process hard to resolve.」它的方案反过来：**small, easy to adapt, and composable**（「Make them your own」），并强调 **They work with any model**。理论血统来自经典工程著作而非自创：*The Pragmatic Programmer*、Eric Evans《领域驱动设计》、Ousterhout《软件设计哲学》、Kent Beck《解析极限编程》。

**针对四类失败模式**：①**Agent 没做我想要的** → **grilling 拷问式访谈**（把方案建模成**设计树**，按**轮次**推进——每轮问整个 **frontier**（前置条件已 settle、现在就能问的决策），每题编号并给出推荐答案；找事实是 Agent 的活、决策是用户的；**frontier 为空才算完成，用户确认前不得动手**）；②**Agent 太啰嗦** → **`CONTEXT.md` 共享语言**（作者自称「可能是本仓库最酷的技术」——把「课程某章节里的一节被『实体化』（即给了文件系统位置）时有问题」压缩成「**实体化级联**（materialization cascade）有问题」，连带收益是命名一致、代码库更好导航、**Agent 思考更省 token**）；③**代码跑不起来** → 反馈回路（静态类型 + 浏览器 + **TDD red-green-refactor**，另有 `/diagnosing-bugs` 纪律化调试环）；④**代码变泥球** → 关心设计（**深模块** deep modules，`/improve-codebase-architecture` 定期扫描）。

**共 38 个技能**（engineering 18 + productivity 7 + misc 4 + in-progress 9，25 个稳定）。**最独特的机制是按「谁能调用」显式二分**：**User-invoked**（只有你敲才触发，职责是**编排**）与 **Model-invoked**（你或 Agent 都能按任务自动触发，承载**可复用纪律**），规则是前者可调后者、**绝不调用另一个 user-invoked**。编排层：`ask-matt`（技能路由器）、`grill-me`/`grill-with-docs`（最受欢迎）、`to-spec`/`to-tickets`（合成规格 / 拆成**带阻塞边的 tracer-bullet 工单**）、`implement`（在**预先商定的接缝**驱动 TDD，提交前走 code-review）、`triage`、`wayfinder`（规划**单会话装不下**的大块工作）、`improve-codebase-architecture`。纪律层：`tdd`、`code-review`（**双轴并行子 Agent**——Standards 查规范与 Fowler 坏味道、Spec 查是否忠实实现原始 issue，**两轴隔离以免互相污染**）、`diagnosing-bugs`（**先建一个「会因这个 bug 变红」的反馈回路**再最小化/假设/插桩/修复/回归）、`codebase-design`、`domain-modeling`、`resolving-merge-conflicts`（逐 hunk 按意图追溯、**绝不 `--abort`**）、`wizard`（生成交互式 bash 向导带人走**只有人能做的步骤**）、`research`、`prototype`。生产力层另有 `wait-what`（消息没看懂就敲，用 `CONTEXT.md` 词汇重讲）、`to-questionnaire`（把**你答不了**的决策变成给能答的人填的问卷）、`handoff`、`teach`、`writing-for-agents`。
